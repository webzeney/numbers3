## 4. 絶対に破ってはいけない約束

ここを守らないとサイトの存在意義が消える。**4つとも実際に事故を起こした、または起こしかけた項目**。

### 4-1. 一度公開した候補数字は、絶対に変えない

`generate.py` の `main()` に、`data/rounds/<回号>.json` が既にあれば保存値で上書きする処理が入っている。
`candidates_ten` があれば位ごと方式、無ければ旧方式、と**保存値で方式そのものも決める**。

> **事故（2026-10-02）**: 乱数の種に `LOGIC_VERSION` を入れていたため、表示上のバージョンを上げただけで
> 第7084回の候補が 1,3,5,9 → 0,5,7,8 → 2,4,5,6 と2回書き換わった。
> 対策として `SELECTION_VERSION` を分離・凍結し、スナップショットによるロックを入れた。
> 詳細は `docs/仕様書.md` の「インシデント記録」。

### 4-2. 選出バージョンは凍結する

```python
SELECTION_VERSION     = "2.1.0-tilted"   # 〜第7092回
SELECTION_VERSION_POS = "3.0.0-pos3"     # 第7093回〜
POS_SWITCH_ROUND      = 7093
```

これらは**乱数の種に使われている**。値を変えると同じ回でも違う候補が出る。
方式を変えるときは、`LOGIC_VERSION`（表示用）ではなく**新しい定数を足して切り替え回を指定する**。既存の定数は書き換えない。

### 4-3. データが古ければ生成を止める（フェイルクローズ）

最新抽選日が5日以上前・回号の飛び・番号の形式不正などがあれば `DataError` を投げて停止する。
**前回値の流用も、勝手な補完もしない。** 旧サイトで4回分ずれた予想を出していた事故の対策。

### 4-4. 当たったことを「手法が良かった」と語らない

候補は210通り（現在は14,400通り）からのほぼ一様な抽選なので、的中は確率16%（現在9%）の事象が起きただけ。
`auto_debate.py` の `REFLECT_SYSTEM` に、AIがこれを書かないよう明示的な禁止条項を入れてある。
一度 Gemini と Claude が「選出アルゴリズムが傾向を捉えた」等と書いて、プロンプトを締め直した経緯がある。

## 5. 日々の運用

### 自動更新

`.github/workflows/update.yml` が以下を実行する。

| cron (UTC) | JST | 用途 |
|---|---|---|
| `0 15 * * *` | 0:00 | 本命 |
| `0 1,3 * * *` | 10:00, 12:00 | 保険 |

1. `python3 generate.py --if-new` を実行（終了コード 0=生成 / 2=データ異常 / 3=生成済み）
2. 差分があればコミット＆プッシュ
3. **終了コードに関わらず FTP でロリポップへアップロード**（サーバーとリポジトリを常に一致させるため）

データ取得元の公開時刻は実測で loto-life が抽選当日19:50、mk-mode が翌10:15。JST 0:00 の実行には3時間以上の余裕がある。

### 手動でデプロイしたいとき

**プッシュだけではデプロイされない。** ワークフローのトリガーは `schedule` と `workflow_dispatch` のみ。

GitHub → Actions → 「ナンバーズ3 自動更新」→ 右上の **Run workflow** → main → Run workflow

### GitHub Secrets（設定済み・値は GitHub 上にのみ存在）

`OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GEMINI_API_KEY` / `FTP_HOST` / `FTP_USER` / `FTP_PASS`

デプロイ先は ロリポップの `/numbers/`。除外は `.git*` `tools/` `__pycache__/` `data/sources/` `data/NUMBERS3_ALL.csv` `.env`。
`docs/引き継ぎ.md` はアップロードはされるが `.htaccess` で遮断している。

## 7. 現在の状態（2026-10-14 時点）

### サイトの構成

```
このサイトは何をしているか   ← 定義ブロック（ページ最上部）
通算収支の台帳
01 第N回の候補
02 検証①：攻略本『別冊宝島271』の鉄則        ← 10項目。z値の解説はここに1回だけ
03 検証②：ネットの攻略サイトが言う手法        ← 12項目。黄金数字・コールドナンバー・曜日
04 3つのAIの予想

07 抽選の偏りの監視
08 AI同士の自動討論
09 登録した仮説                              ← p値の解説はここに1回だけ
10 保存版ページ
```

### 検証の結論（現時点）

**攻略本10項目＋攻略サイト12項目のうち、何も考えずに選ぶより当たりやすかった手法は0個。**

特に記録しておくべき結果：

- 「裏数字26.1%」「後数字59.5%」は、**主張値そのものが基準（27.10% / 60.76%）より低い**
- 黄金数字は 選定期間12.15%（z=+4.69）→ **選定後9.99%（z=−0.03）**。後知恵の見本
- コールドナンバーは攻略サイト間で主張が正反対。実測ではご無沙汰の長さと無関係
- 曜日は金曜（主張された曜日）が基準どおりで、代わりに水曜が z=+2.01。多重比較の見本

### 収支

第7082回から10回判定済み。購入32,000円 / 当選9,300円 / **収支 −22,700円**（回収率29.1%、理論値43.2%）。
的中は第7085回の1回のみ（+6,100円）。

### 選出方式の変更（重要）

**第7093回から、十の位3数字 × 一の位3数字 = 9口（1,800円）に変わる。**
これまでは4数字1組を両方の位に流用して16口（3,200円）だった。

- 的中率は16%→9%に下がるが、**期待回収率は43.2%で不変**（1口が押さえるのは100通りのうち1通りなので、口数を変えても率は動かない）
- 選択肢の空間は 210通り → 120×120 = 14,400通り
- 位ごとの採点では「桁別ひっぱり」を1点加算する（原典で唯一、位を指定した主張のため）
- **第7092回までは旧方式のまま。保存版ページも当時の形で残っている**

### 気になっている数字

新方式で重み付けあり/なしを全履歴6,891回で比較したところ：

| | 重み0.2（現行） | 重みなし（一様） |
|---|---|---|
| ミニ的中率 | **8.62%** | **9.49%** |

差 −0.87ポイント、標準誤差0.488、z=−1.78 で**有意ではない**が、値としては重み付けのほうが低い。
これまで測った中では最大のズレ。**この傾向が続くなら `TILT_WEIGHT` を 0 にして完全な一様抽選にする**。
サイトの06にもその旨を明記してある。

## 8. 過去の事故と対策（繰り返さないために）

| 事故 | 原因 | 対策 |
|---|---|---|
| 公開済みの候補が2回書き換わった | 乱数の種に表示用バージョンを入れていた | `SELECTION_VERSION` を分離・凍結＋スナップショットロック |

| 保存版ページが全滅 | ミニ対応でキー名を変えたのに、旧キーを参照したままだった | 新旧どちらのキーでも動くフォールバックを入れる |
| AIが因果を語った | 所見のプロンプトが緩かった | `REFLECT_SYSTEM` に禁止条項を明記 |
| 無限ループ | 候補生成のループに上限が無かった | 回数上限＋フォールバックを入れる |

`index.html` を編集するときのルール：
1. Python で `assert s.count(old) == 1` を必ず付けてから置換する
2. CSS は既存ブロックを書き換えず、`</style>` の直前に追記する
3. 編集後に `<script>` 内のJSを `node --check` で構文チェックする
4. ローカルサーバーを立てて、デスクトップとモバイル両方で目視確認する

## 10. リモート運用について

Mac mini を母艦にして他端末からつなぐ構成を取る場合、確認しておくこと。

1. **Mac mini にデスクトップ版 Claude Code を入れ、このリポジトリを開いておく**
2. **自動ログイン・スリープ設定** — システム設定 → バッテリー/省エネルギー で「ディスプレイがオフのときコンピュータを自動でスリープさせない」をオンにする。スリープすると母艦として応答しない
3. **リモート接続の手段** — Claude Code 側のリモート機能（別端末のセッションからつなぐ）を使う場合、Mac mini 側と接続元の両方で同じアカウントにサインインしておく必要がある。**実際の設定項目はアプリ内で確認すること**（バージョンで名称が変わる）
4. **代替手段** — うまくいかない場合は、Mac mini に SSH で入って `claude` を起動する、あるいは画面共有を使う
5. **このリポジトリに限れば、実は母艦は必須ではない** — サイトの更新は GitHub Actions が全部やるので、Mac mini が落ちていてもサイトは毎日更新される。母艦が要るのは**開発作業をするとき**だけ

> 注意: `.env` は git に乗らない。Mac mini でも別途作る必要がある。
> 逆に言えば、キーは Mac mini とGitHub Secrets の2か所にしか置かないようにすると管理が楽。
