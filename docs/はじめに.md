# 第1部 — 左メニューに出す手順（人間がやる）

デスクトップ版の左メニューには「**そのPCで開いた作業フォルダ**」が並びます。
PCごとに1回だけ、下の2ステップが必要です。同期はされません。

## ステップ1: フォルダを用意する

ターミナルを開いて、**そのまま貼り付けて実行**します。

```bash
mkdir -p ~/Desktop/works && cd ~/Desktop/works
git clone https://github.com/webzeney/numbers3.git "numbers3サイト構築"
```

> **`cd ~/Desktop/works` を必ず先に実行してください。**
> 別のフォルダの中で走らせると、リポジトリが入れ子になって事故ります（実際に起きました）。

GitHubの認証を求められたら webzeney アカウントで通します。
パスワードではなくトークンかブラウザ認証を使ってください。

3台とも**同じフォルダ名**にすれば、どのPCでも左メニューの見え方が揃います。

## ステップ2: デスクトップ版で開く

デスクトップ版 Claude Code を起動し、作業フォルダとして次を開きます。

```
~/Desktop/works/numbers3サイト構築
```

これで左メニューに「**numbers3サイト構築**」と表示されます。一度開けば、そのPCでは残り続けます。

## ステップ3: 続きから始める

開くと新しい会話が始まるので、**最初のメッセージに次をそのまま貼ってください。**

> `~/Desktop/works/numbers3サイト構築` のナンバーズ3検証サイトの作業を続けます。
> まず `docs/はじめに.md` を読んで、第2部の内容を把握してください。
> そのあと必要に応じて `docs/運用メモ.md` と `docs/仕様書.md` を読んでください。

## 複数のPCで作業するときの注意

- 作業を**始める前**に `git pull`
- 作業が**終わったら** `git push`

これを忘れると、別のPCで加えた変更と衝突します。
Claudeに「作業を始めます」と伝えれば、毎回確認してもらえます。

# 第2部 — いまの続き（Claudeが読む）

**この節を読んだら、ユーザーに「どこまで把握したか」を3行程度で伝えてから作業に入ってください。**

## このサイトは何か

**攻略本やネットで「当たる」と言われている手法が、本当に当たるのかを全履歴で検証するサイト。**
候補数字も出すが、それは検証を続けるための記録装置であって、当てることが目的ではない。

- 公開先: https://numbers.ota9.site/
- リポジトリ: https://github.com/webzeney/numbers3
- 更新: GitHub Actions が毎日自動実行（JST 0:00 ほか）→ 生成 → コミット → FTPでロリポップへ

## 最優先の制約（破ると取り返しがつかない）

1. **一度公開した候補数字は絶対に変えない。** スナップショットに保存された値が常に優先される
2. **選出バージョン（`SELECTION_VERSION` 系）は凍結。** 乱数の種に使われているので、
   値を変えると過去の回の候補まで変わる。方式を変えるときは新しい定数を足して切り替え回を指定する
3. **データが古ければ生成を止める**（フェイルクローズ）。前回値の流用も補完もしない
4. **当落を方法の良し悪しに結びつけない。** 的中は確率どおりの事象が起きただけ

詳細と事故の経緯は `docs/仕様書.md`、運用の全体像は `docs/運用メモ.md` にある。

## いま判断待ちになっていること（最優先）

### `TILT_WEIGHT` を 0 にして完全な一様抽選にするか

**3つのAIが全員一致で「廃止すべき」と結論した**（討論 第5回・`data/debates/0005.json`）。

- 桁別ひっぱりの実測は 百10.22% / 十9.99% / 一10.11%（基準10.00%）で、**重みの根拠そのものが否定されている**
- 重み0.2と一様の比較は 16.47% vs 15.82%、z=1.04 で**有意差なし**
- 「検証サイトなのに、効かないと分かっているものを選出に混ぜているのはおかしい」というのが3者共通の論拠

**ユーザーはまだ実施を決めていない。** やる場合は次の手順になる。

1. **新しい選出バージョンを足す**（例: `SELECTION_VERSION_FLAT = "4.0.0-flat"` と `FLAT_START_ROUND`）。
   既存の `SELECTION_VERSION = "2.1.0-tilted"` は書き換えない
2. 切り替えは**次の未公開回から**。公開済みの回は一切動かさない
3. 05「選び方を変えた経緯」の表に1行追加し、**なぜやめたかを隠さず書く**
4. `tools/compare_weight.py` の扱いを決める（比較対象が無くなるため、過去の記録として残すか）

## 作業するときの約束

- **手元で `generate.py` を走らせるときは `--no-ai` を付ける。** AIを呼ぶ処理はGitHub Actions側に寄せた
- **AI討論は GitHub の画面から実行する。** Actions → 「AI討論を実行」→ 議題を入力 → Run workflow
- **`index.html` を編集するときは、Pythonで `assert s.count(old) == 1` を付けてから置換する。**
  過去に広い範囲の置換でCSSを2回破壊している
- CSSは既存ブロックを書き換えず、`</style>` の直前に追記する
- 編集後は `<script>` 内のJSを `node --check` で構文チェックし、
  ローカルサーバーを立ててデスクトップとモバイル両方で目視確認する
- **プッシュしただけではデプロイされない。** GitHub → Actions → 「ナンバーズ3 自動更新」→ Run workflow
