# ナンバーズ3ミニ 候補選出システム 仕様書

**対象はミニ（下2桁）**。3桁のストレート／ボックスではなく、十の位・一の位の2桁を狙う。

| | 確率 | 平均当選金額(直近1084回) | 200円あたりの期待値 |
|---|---|---|---|
| ストレート | 1/1000 = 0.1% | 86,793円 | 約87円 |
| ボックス | 構成による | 18,711円 | 約87円 |
| **ミニ** | **1/100 = 1.0%** | **8,636円** | **約86円** |

還元率はどれも同じ（約43%）。ミニは的中頻度が10倍になる代わりに賞金が1/10。
**記録が10倍速く貯まる**ため、検証を目的とするこのサイトにはミニが適している。

候補4数字から作る買い目は 4×4 = **16通り**（3,200円）。的中確率は (4/10)² = **16.0%**。

バージョン: `3.0.0-mini`（選出方式のバージョンは `2.1.0-tilted` で凍結）
記録開始: **第7082回（2026-09-30）から**。旧サイトのアーカイブは引き継がない
決定の経緯: Claude / GPT-5.5 / Gemini による8周の討論（`討論台本.md`）と、全履歴7080回の検定（`検定レポート.md`）、6980回のバックテスト（`バックテスト結果.md`）に基づく。

## 1. このシステムが解決した問題

旧システムは0〜9を5要素（ひっぱり・頻度・勢い・連番ほか）でポイント化し、**合計上位4つを決定論的に選んで**いた。これには2つの構造的欠陥があった。

1. **相関した特徴の多重カウント** — 5要素はすべて「最近よく出た数字」に加点する同一方向の信号だった。独立な観点ではないため、一度上位に立った数字が全要素で勝ち続ける
2. **負のフィードバックの不在** — 選ばれ続けたことへの減点も、選出履歴の参照もなかった

結果として「6」が最長14回連続で候補入りし、候補セットの連続重複は平均2.96/4個（無相関なら1.60）に達していた。旧ロジックを再構成して6980回のバックテストにかけたところ、**同じ数字が最長60回連続で選ばれ続ける**ことが確認された。これは実装の細部ではなく構造から必然的に生じる。

## 2. 選出方式

### 2.1 210通りからの抽選（原典への軽い傾き付き）

0〜9から4つを選ぶ組み合わせは **210通り（10C4）**。ここから1組を選ぶ。
完全な等確率ではなく、**宝島本の手法に該当する数字を多く含む組をわずかに選ばれやすく**する。

```
各数字の原典ポイント = ひっぱり + スライド + 裏数字 + 合わせ数字 に該当する数（0〜4）
組の重み = exp(0.2 × その組4数字のポイント合計)
```

重み0.2では、選ばれやすさの幅はおおむね **0.3〜3倍** に収まる。

**この傾きを入れても数字ごとの偏りは発生しない**（直近3000回で検証）。

| 重み | 平均カバー | 採用χ² | 最多採用率 | 最長連続 | 選ばれやすさの幅 |
|---|---|---|---|---|---|
| 0.0（一様） | 1.205 | 4.0 | 41.3% | 10回 | 1.0倍 |
| **0.2（採用）** | 1.186 | **4.8** | 41.2% | 9回 | 0.33〜3.0倍 |
| 0.3 | 1.200 | 9.2 | 41.4% | 9回 | 0.18〜5.0倍 |
| 1.0 | 1.180 | 4.6 | 41.4% | 12回 | 0.00〜52.3倍 |

理由は、ひっぱり・スライド・裏数字・合わせ数字が**すべて「前回の当選番号」を基準にした相対的な手法**だから。前回番号が毎回変わるため、特定の数字が固定的に有利になることがない。
旧サイトの「6」固着は、頻度・勢いという**絶対的でゆっくりしか動かない指標**が原因であり、原典の手法そのものは犯人ではなかった。

採用理由は、6980回のバックテストで以下が確認されたため。

| 指標 | 旧ロジック | 改良ポイント制 | **一様ランダム** | 理論基準 |
|---|---|---|---|---|
| 平均カバー桁数 | 1.197 | 1.198 | 1.221 | 1.200 |
| 連続回のセット重複 | 2.89 | 1.59 | 1.61 | 1.60 |
| 同じ数字の最長連続採用 | 60回 | 6回 | 12回 | — |
| 採用回数のχ² | 376.4 | 68.4 | **3.4** | 0 |

**予測精度は3方式すべて同じ**（標準誤差0.010に対し全て1.20付近）。精度で選べない以上、採用率の偏りが最も小さい方式を採る。

### 2.2 乱数の種

```
種の材料 = "{対象回号}:{直近確定番号}:{ロジック版}"
ハッシュ = SHA-256(種の材料 + "#" + 拒否カウンタ)
```

- **前回の結果が確定するまで次回の候補を計算できない**（事前に知ることが不可能）
- 確定後は誰でも同じ値を再現できる（`generate.py --verify` で検証可能）
- 日時・タイムゾーン・実行環境に一切依存しない
- SHA-256の上位64ビットを[0,1)の一様乱数に変換し、重みの累積分布で組を選ぶ

### 2.3 伝統手法の扱い

ひっぱり・スライド・裏数字・合わせ数字は、**選出に軽く関与する（重み0.2）ほか、タグとして表示**する。
予測力がないことは下表のとおり全履歴で確認済みで、傾きは「読み物としての納得感」のために入れている。当たりやすさは変わらない（平均カバー桁数が基準1.200のまま動かないことで確認できる）。

理由は全履歴7080回の検定結果（基準27.10% = どの数字も3桁中に出る確率）。

| 鉄則 | 実測 | z値 | 判定 |
|---|---|---|---|
| ひっぱり | 27.26% | +0.49 | 有意差なし |
| スライド | 27.12% | +0.07 | 有意差なし |
| 裏数字 | 27.36% | +0.81 | 有意差なし |
| 合わせ数字 | 26.94% | −0.49 | 有意差なし |

**採点に混ぜると、予測力のない俗説が再び固着を生む**（GPTの指摘）。タグは実測的中率とセットで表示し、当たりやすさを主張しない。

## 3. データ鮮度フェイルクローズ

旧サイトでは、2026-09-29 05:17 に生成された `latest.json` が第7076回（抽選日 2026-09-22）を「最新」と表示し、**すでに抽選済みの第7077回（2026-09-23・当選番号187）を予想対象にしていた**。4回分のずれである。

`validate()` は以下を検査し、1つでも該当すれば **DataError を投げて候補生成を停止**する。前回値の流用や勝手な補完は行わない。

- 回号の重複
- 回号の非昇順
- 回号の飛び
- 当選番号の形式不正（3桁の数字でない）
- 最新抽選日が5日より前（`MAX_GAP_DAYS`）
- 最新抽選日が未来

| 取得元 | 形式 | 更新タイミング（実測） |
|---|---|---|

いずれも2026-09-29 第7081回（18:45抽選）で5分間隔の監視により実測。

- 両方失敗したらローカルの履歴で続行し、鮮度チェックに委ねる

## 4.7 3つのAIの予想

ChatGPT / Claude / Gemini に、直近10回の当選番号だけを渡して予想させる。

- 1回号につき**1回だけ**問い合わせ、`data/ai/<回号>.json` にキャッシュする
- キー未設定・API失敗でもサイト生成は止まらない（その枠が「未設定」「取得失敗」になるだけ）
- 抽選後、同じ当選番号で自動採点し、AIごとの通算成績（本命的中・平均カバー桁数）を蓄積する
- 環境変数: `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GEMINI_API_KEY`
- モデルは `OPENAI_MODEL` / `ANTHROPIC_MODEL` / `GEMINI_MODEL` で上書き可
- 費用は3AI合計で1日1円未満

**この欄の目的は当てることではない。** 3つのAIが等しく当てられないことを記録し続けるための欄である。

## 4.8 保存版ページ

各回の予想を `data/rounds/<回号>.json` に丸ごと保存し、`?round=7082` で開ける。

- 抽選後、結果と検証コメントが**自動で書き足される**（AIの予想も同時に採点される）
- `?round=demo` は表示例（架空データ）。一覧には出ない

## 4.9 AI同士の自動討論

人間の指示なしで3つのAIが議論する。`auto_debate.py`

| 種類 | タイミング | 内容 | 保存先 |
|---|---|---|---|
| 結果への所見 | 抽選結果を取り込んだ直後 | 3者が1〜2文ずつ | 各回のスナップショット `ai_comments` |
| 設計の討論 | 7日ごと | 3者が1周（3発言） | `data/debates/NNNN.json` |

**守っていること**

- **提案はサイトに自動適用しない。** 採用は人間が決める（承認制）。
  AI自身が決めた「ルールは凍結し変更履歴を残す」「提案者は自分の案の採否判断から外れる」
  という原則を壊さないため、また公開済みの数字が勝手に変わる事故を防ぐため
- 1回の討論は**3発言まで**。費用とノイズを抑える
- APIが落ちてもサイト生成は止まらない
- 議題は前回の最終発言にある「次回の論点」を引き継ぐ。拾えなければ既定の議題リストから順に使う

**所見の指示（重要）**

最初の実装では、的中した回にGeminiが「選出アルゴリズムが傾向を適切に捉えていた」、
Claudeが「4数字選定の有効性を示す一例」と書いた。いずれも根拠のない因果の主張であり、
このサイトが最も避けるべき種類の文章だった。そのため指示を次のように厳格化した。

- 的中を「アルゴリズムが傾向を捉えた」「選定の有効性を示す」と語ってはならない
- 外れを「惜しかった」「あと一歩」と語ってはならない。近さに意味はない
- 次回の予想や、出やすい数字についての示唆を書いてはならない
- 書くべきは、事実の確認・記録上の位置づけ・確率的な解釈の注意喚起のいずれか

これは「自動化しても人間の点検が要る」ことの実例として残しておく。

## 5. 運用

```bash
python3 generate.py --if-new   # 定期実行はこれ（生成済みなら何もせず終了コード3）
python3 generate.py --refresh-ai  # AIの予想を取り直す（キーを後から足したとき）
python3 generate.py --no-fetch # ダウンロードせずローカルCSVで生成
python3 generate.py --no-ai    # AIへの問い合わせを省く
python3 generate.py --verify   # 出力の再現性を検証
python3 generate.py --now 2026-09-30T20:00   # 現在時刻を差し替える（テスト用）
python3 tools/simulate.py      # 数日分の動きをシミュレートする（テスト用）
```

### cron

```
0 0 * * *     cd /path/to/site && /usr/bin/python3 generate.py --if-new >> generate.log 2>&1
0 1-12 * * *  cd /path/to/site && /usr/bin/python3 generate.py --if-new >> generate.log 2>&1
```

- 両取得元とも抽選当日20〜21時には公開されるため、**0時の実行で毎日更新される**
- 10時・12時は保険（取得元が遅れた場合に拾う）
- `--if-new` があるので何度叩いても安全。APIへの問い合わせも生成が走った1回だけ
- 3つのAPIキーをcronの環境から見えるようにすること（cronは `~/.zshrc` を読まない）

## 5.5 インシデント記録: 公開済みの候補が書き換わった（2026-10-02）

**何が起きたか**: 乱数の種に `LOGIC_VERSION` を含めていたため、サイトのバージョンを
上げるだけで、まだ抽選前の回の候補数字が変わってしまった。

第7084回の候補は実際に二度変わった。

| 時点 | 候補 | 種の材料 |
|---|---|---|
| 自動実行（2.1.0） | **1,3,5,9** | `7084:606:2.1.0-tilted` |
| 手動更新（2.2.0） | 0,5,7,8 | `7084:606:2.2.0-tilted` |
| 手動更新（2.3.0） | 2,4,5,6 | `7084:606:2.3.0-tilted` |

「一度公開した候補は変わらない」という設計の根幹が壊れていた。

**対処**:

1. 乱数の種に使うバージョンを `SELECTION_VERSION` として分離し、**選出方式を変えない限り凍結**する
   （現在 `2.1.0-tilted`。サイト全体のバージョン `LOGIC_VERSION` とは別管理）
2. **保存版ページが既にある回は候補を作り直さない**。再計算値が違っても最初の値を維持し、
   破棄したことを標準エラーに出す（構造的な歯止め）
3. 第7084回は最初に公開された **1,3,5,9** に戻した

## 6. 意図的に採用しなかったもの

| 案 | 却下理由 |
|---|---|
| 頻度・勢いによるポイント制（改良版含む） | 精度優位がないのに採用率χ²=68.4の偏りが残る。偏りは読み物のための副作用でしかない |
| セット距離ペナルティの強化 | 連続回の重複が0.04個まで落ち、「前回の数字を必ず避ける」という逆向きの癖が生まれる。多様性の目標は0ではなく無相関（1.60） |
| 直近当選数字の強制排除 | 根拠が薄く、ギャンブラーの誤謬そのもの |
| 直近成績によるパラメータ自動選択 | サンプルが少なく過学習装置になる |
| 環境要因（湿度・気温）の加点 | 高湿度期と低湿度期の同質性χ²=8.24で差が検出されない。仮に微小な偏りがあっても、還元率およそ45%の壁は覆せない。検定と報告に留める |
| 機械学習による予測 | 全履歴で予測可能な構造が検出されない以上、学習対象が存在しない |
